# Remotely Save HTTP

English | [简体中文](./README.zh-cn.md)

A personal Obsidian plugin based on [Remotely Save](https://github.com/remotely-save/remotely-save), focused on WebDAV. It supports WebDAV endpoints over **HTTP or HTTPS**, including an HTTP server reachable through Tailscale. Sync works in both directions and can run on a schedule or manually.

## What this build supports

- One remote service: WebDAV.
- Manual sync from the ribbon icon, the **Sync now** button in settings, or the **Start sync** command.
- Silent scheduled merge sync every 5 seconds by default, with 15 second, 1 minute, 5 minute and Off options. Markdown changes use smart conflict handling.
- A slim purple progress bar at the top shows manual sync progress without text. The first automatic sync after opening Obsidian also shows it; after a visible success, automatic sync keeps running but shows the bar again only after 30 minutes. File progress advances after completed operations and reaches 100% only on success. Errors always show the bar and the reason.
- WebDAV Basic or Digest authentication, a configurable remote folder, Depth header, and custom request headers.
- Desktop and mobile Obsidian, as declared in the plugin manifest.
- Space then Enter at the end of a Markdown list item creates a nested child item.
- Narrow the editor to one Markdown heading section or list item and its children while writing.

This build does not enable other cloud providers or end-to-end file encryption. It does not sync the vault's `.obsidian` configuration folder. Back up your vault before the first sync or when switching from another sync plugin: bidirectional sync can update or delete files on either side.

## Install with BRAT (including Obsidian Mobile)

This plugin is not in Obsidian's community plugin browser. Install [BRAT](https://github.com/TfTHacker/obsidian42-brat), use its **Add a beta plugin for testing** command, and enter `https://github.com/guangtouge82/remotely-save-http`. Select the latest release, then enable **Remotely Save HTTP** in Obsidian's community plugin settings.

BRAT downloads `manifest.json`, `main.js`, and `styles.css` from this repository's GitHub Release assets. The repository's source tree alone is not an installable release.

## Nested list items

While editing a Markdown list, type a space after the item's text and press Enter. For example, `- Parent ` becomes:

```markdown
- Parent
  - Child
```

The cursor moves to the new child item, where you can type `Child`. Task list items keep their checkbox type: `- [ ] Parent ` creates an indented `- [ ] ` child. A completed parent also creates an unchecked child. Enter without a trailing space retains Obsidian's normal sibling-item behavior. Plain text and selections are unaffected. Numbered lists work too.

## Narrow heading and list editing

Place the cursor on a Markdown heading or list item (including a `- [ ]` task), or select its text, then choose the narrow command from the editor context menu. You can also run **Narrow to current node / Exit narrow mode** from the command palette. For a heading, the editor shows its section through the next heading of the same or higher level. For a list item, it shows that item and its indented children. Edits still save to the original note. Click **Exit narrow mode** at the top right of the editor, run the command again, or use the context menu to reveal the full note with the focused node centered vertically. Esc remains available to Obsidian's Vim mode. Narrow mode does not change the Markdown structure.

## Install from source

1. Clone this repository and build it with Node.js and npm:

   ```sh
   npm install
   npm run build
   ```

2. Create `<vault>/.obsidian/plugins/remotely-save-http/` and copy these three files into it:

   ```text
   main.js
   manifest.json
   styles.css
   ```

   `main.js` is generated by the build and is not tracked in Git. Do not copy `data.json` from another vault unless you intentionally want to reuse its settings and credentials.

3. In Obsidian, allow community plugins if the vault is in Restricted Mode, then enable **Remotely Save HTTP**. If Obsidian was already open while you copied the files, restart Obsidian or reload the plugin.

The plugin ID is `remotely-save-http`. Use that exact directory name.

## Configure WebDAV

Open **Settings → Remotely Save HTTP** and fill in:

| Setting | What to enter |
| --- | --- |
| Server address | The full WebDAV endpoint, for example `http://your-tailnet-host:8080/dav/` or `https://example.com/dav/`. Include the scheme and any required port and path. |
| Username and password | Your WebDAV credentials, if the server requires them. |
| Folder name | The folder for this vault under the WebDAV endpoint. If left empty, the Obsidian vault name is used. The page previews the resulting path. |

The plugin creates the remote vault folder when needed. On another device syncing the *same* vault, use the same WebDAV endpoint and folder name. Give unrelated vaults different folders.

The collapsed **Advanced options** section contains Basic/Digest authentication, the Depth header (`1` by default, or `infinity` if your server supports it), and optional custom headers in `Header: value` format, one per line.

1. Click **Check connection**. This check may create and remove a temporary file on the server; it is not read-only.
2. Once the check succeeds, click **Sync now**, use the ribbon icon, or run **Start sync** from the command palette.

The connection and sync buttons require a valid `http://` or `https://` address. If the check fails, verify the endpoint path, port, credentials, and server reachability.

## Scheduled merge sync

The **Scheduled merge sync** setting defaults to every 5 seconds while Obsidian is open. Choose 15 seconds, 1 minute, 5 minutes, or Off as needed. Each run reads the server's file list first and compares it with the local vault and the previous sync record; only detected changes cause file transfers. When the WebDAV server provides ETags, the comparison also detects changes with the same file size and modified time. A newer remote change is pulled, a newer local change is uploaded, and changes on both sides use smart conflict handling. The former 50% mass-change limit is disabled in this WebDAV build, so it cannot stop a valid sync. Scheduled checks show the top progress bar on the first run and at most once per 30 minutes after a visible success, without update notices or sync icon animation. Errors always show the reason. A scheduled run is skipped if another sync is active or no valid WebDAV address is configured. On mobile, timers pause while Obsidian is suspended in the background.

New files and folders beginning with `_` are included. Obsidian's `.obsidian` settings and other dot-prefixed paths remain excluded.

Files larger than 64 MiB are skipped without deleting either copy. Obsidian's renderer reads whole files into memory, and transferring multi-gigabyte files can crash the app. Notes and smaller attachments continue syncing; transfer oversized files separately.

When both devices change a Markdown file, smart conflict handling attempts to merge it. Edits to the same lines can produce conflict markers that need review. Files that cannot be merged are preserved as separate copies. Frequent sync reduces the conflict window but cannot guarantee conflict-free edits across devices.

## HTTP and local settings

HTTP does not provide HTTPS transport protection. Use it only where you trust the network path, such as your intended Tailscale connection; choose HTTPS when available. Connect each device to the correct Tailnet before syncing through a Tailscale address.

WebDAV settings, including credentials, are stored locally in the vault's plugin data. Keep that file out of public repositories. This build does not encrypt synced file contents end to end.
